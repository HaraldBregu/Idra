# Anthropic Skills

This page summarizes Anthropic Agent Skills usage from official Anthropic docs
and Claude Help Center pages checked on May 22, 2026. It is intentionally
paraphrased rather than copied from the source pages.

## What They Are

Anthropic Agent Skills are folders of instructions, metadata, and optional
resources that Claude can load when a task matches the skill description. They
are meant for repeatable expertise: document creation, brand workflows,
analysis procedures, organization conventions, and personal work styles.

Skills differ from prompts because they are installed once and then loaded
on-demand. Claude sees lightweight metadata first, loads `SKILL.md` only when a
skill is relevant, and accesses extra resources only when the task needs them.

Agent Skills are not eligible for Zero Data Retention. Treat skill definitions,
execution data, and generated files according to Anthropic's standard retention
terms for the surface being used.

## Where Anthropic Uses Skills

| Surface | Skill types | How they are enabled | Invocation model |
| --- | --- | --- | --- |
| Claude API | Anthropic-managed and custom skills | Messages API `container.skills` plus code execution | Claude chooses relevant skills from metadata during the request. |
| claude.ai | Anthropic, custom, shared, organization, and partner skills | Settings or Customize > Skills, with code execution enabled | Claude uses enabled skills automatically when relevant; users can be explicit in prompts. |
| Claude Code | Custom skills | Local filesystem skill directories with `SKILL.md` | Claude discovers custom skills locally and loads them when relevant. |
| Claude Platform on AWS and Microsoft Foundry | Same model as Claude API | Skills API on those platforms | Same runtime behavior as Claude API. |

Anthropic-managed document skills include PowerPoint (`pptx`), Excel (`xlsx`),
Word (`docx`), and PDF (`pdf`). They are available in the API and claude.ai.

## Claude API Usage

In the Claude API, skills run through the code execution environment. A request
must include the code execution tool and the skills in the `container`
parameter.

Required beta headers:

- `code-execution-2025-08-25`
- `skills-2025-10-02`
- `files-api-2025-04-14` when uploading or downloading files

Minimal shape:

```python
response = client.beta.messages.create(
    model="claude-opus-4-7",
    max_tokens=4096,
    betas=["code-execution-2025-08-25", "skills-2025-10-02"],
    container={
        "skills": [
            {"type": "anthropic", "skill_id": "pptx", "version": "latest"}
        ]
    },
    tools=[{"type": "code_execution_20250825", "name": "code_execution"}],
    messages=[{"role": "user", "content": "Create a five-slide roadmap deck."}],
)
```

For custom skills, use `type: "custom"` and the generated custom `skill_id`:

```python
container = {
    "skills": [
        {
            "type": "custom",
            "skill_id": "skill_01AbCdEfGhIjKlMnOpQrStUv",
            "version": "latest",
        }
    ]
}
```

API behavior:

- Anthropic and custom skills use the same `container.skills` shape.
- A request can include up to eight skills.
- Anthropic skill ids are short names such as `pptx`, `xlsx`, `docx`, and
  `pdf`.
- Custom skill ids are generated by the Skills API.
- Anthropic-managed versions are date-based or `latest`; custom versions are
  generated version ids or `latest`.
- Pin exact versions for production stability. Use `latest` for active
  development.
- Generated files are returned as file ids from code execution results and must
  be downloaded through the Files API.
- Multi-turn work can reuse a container id so the same container state remains
  available.
- Long-running skill operations can return `pause_turn`; continue by sending
  the assistant content back in a follow-up request with the same container.

## Managing Custom Skills In The API

A custom API skill is uploaded through the Skills API as a package. The package
can be a zip archive or individual file objects.

Required package shape:

```text
my-skill/
├── SKILL.md
├── references/
│   └── workflow.md
└── scripts/
    └── generate_report.py
```

`SKILL.md` must be at the package root and start with YAML frontmatter:

```markdown
---
name: brand-guidelines
description: Apply Acme brand rules to presentations and client-facing documents.
---

# Brand Guidelines

Use the approved colors, typography, and layout rules when creating external
documents.
```

API package constraints from Anthropic's docs:

- `SKILL.md` is required at the top level.
- Uploaded files must share a common root directory.
- Total upload size must be under `30 MB`.
- `name` must be lowercase letters, numbers, and hyphens, with a maximum of
  `64` characters.
- `description` must be non-empty, cannot contain XML tags, and has a maximum
  of `1024` characters in the API docs.
- The words `anthropic` and `claude` are reserved in skill names.

List skills through the Skills API to see Anthropic-managed and custom skills.
Use the source filter to narrow results to `anthropic` or `custom`.

To delete a custom skill, delete all of its versions first, then delete the
skill record.

## How Claude Loads Skills

Anthropic describes skill loading as progressive disclosure.

| Level | Loaded when | Contents |
| --- | --- | --- |
| Metadata | Always available to Claude when the skill is installed or attached | `name` and `description` from frontmatter. |
| Instructions | Only when Claude decides the skill is relevant | The body of `SKILL.md`. |
| Resources and code | Only if referenced and needed | Extra markdown files, templates, assets, and scripts. |

In the API, specified skill files are copied into the code execution container
under `/skills/{directory}/`. Claude sees skill metadata, decides when a skill
applies, loads the relevant instructions, and can compose multiple skills in
one workflow.

This model keeps context usage low: large references and scripts do not consume
context until Claude actually needs them. Scripts are useful when the workflow
must be deterministic or fragile.

## claude.ai Usage

In claude.ai, skills require code execution and file creation to be enabled.

Common user flow:

1. Enable code execution in Settings or organization settings.
2. Open Customize > Skills.
3. Toggle built-in Anthropic skills on or off.
4. Upload custom skills as zip files when needed.
5. Prompt naturally, or explicitly ask Claude to use a named skill.

With Anthropic skills enabled, Claude automatically applies document skills
when a request calls for files such as presentations, spreadsheets, Word
documents, or PDFs.

Custom skills uploaded by an individual user are private to that account unless
they are shared or provisioned through Team or Enterprise controls.

Team and Enterprise organizations can:

- Provision approved skills organization-wide.
- Allow or block skill sharing.
- Share skills with specific colleagues.
- Publish skills to an organization directory.
- Enable skills by default for members.

Shared skills are view-only for recipients. If the original skill is updated,
recipients receive the updated version.

## Excel And PowerPoint Add-Ins

Claude for Excel and Claude for PowerPoint can use enabled skills from the
user's Claude settings.

Triggering options:

- Describe the task naturally and let Claude match a relevant skill.
- Type `/` in the add-in sidebar and choose a skill directly.

Claude adapts the skill to the surface. A skill that writes a document in one
surface may produce workbook analysis in Excel or presentation changes in
PowerPoint.

## Authoring Guidance

Good Anthropic skills are focused and concise.

- Solve one repeatable task instead of bundling many unrelated workflows.
- Write the description as a trigger: what the skill does and when Claude should
  use it.
- Put essential instructions in `SKILL.md`.
- Move large references, templates, and examples into supporting files.
- Add scripts when exact behavior matters more than flexible reasoning.
- Include examples when they clarify the expected output.
- Test with prompts that should and should not trigger the skill.
- If Claude does not invoke the skill when expected, improve the description
  before adding more instruction text.

## Security And Runtime Constraints

Treat skills like software dependencies, not inert documentation.

Review before enabling:

- `SKILL.md`
- referenced markdown files
- scripts
- assets
- package dependencies
- URLs and network calls
- file access patterns
- instructions that hide actions, bypass safety, or exfiltrate data

Important runtime constraints:

| Surface | Constraint |
| --- | --- |
| Claude API | No network access from skills, no runtime package installation, isolated containers. |
| claude.ai | Network availability can vary by user and admin settings. |
| Claude Code | Skills run with the local environment's network and filesystem access. |

Skills do not automatically sync across surfaces. A skill uploaded to claude.ai
is separate from a skill uploaded through the Claude API, and Claude Code skills
are filesystem-based.
