# Release Notes Tone Guide

## Default Tone

Use clear, direct product language. Prefer user outcomes over implementation details.

## App Store Or Consumer Updates

- Keep paragraphs short.
- Avoid jargon.
- Mention the top benefit first.

## Developer Releases

- Keep API names, package names, and migration notes precise.
- Group breaking changes separately.
- Include commands only when the user provided or requested them.

## Internal Updates

- Include owner, rollout status, and risk only if those details are present in the source material.
- Avoid implying a feature is complete when the source says it is experimental or staged.
